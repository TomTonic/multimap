# Jobs for the arm64 machine, run by the user with bench/remote/arm-run.sh (see its header).
# <id> <ref> <baseline-ref or -> <duration-minutes> [tags=a,b] <arguments of cmd/bench>
#
# The arm64 machine is an M1 Pro with 16 GB: 8 performance and 2 efficiency cores, 128-byte cache
# lines. In the serial regime the processes of a scenario run one after another, so -maxprocs is
# only how many a scenario may use at most (24 is cheap here). No memory phase beyond 256K keys
# (-memn 262144) and no 1M keys at all: a process at 1M keys holds 4-5 GB.
#
# Jobs are added by the agent as the steps of docs/redesign/PLAN.md need them. Refs are commits,
# so that a job means the same thing when it is run later.

# Gate 0 of the redesign: an A/A run, the same code against itself, to see how much the M1 Pro
# scatters (docs/redesign/PLAN.md). Read with care if an interval is wider than +-3 points.
a0 6b06dd2 6b06dd2 5 -suite dev -keys u64,str -sizes 4096,16384 -ops valuesFor,valuesBetween,churn,build -vs baseline -minprocs 4 -maxprocs 8 -skipmem

# a0 ran on 2026-10-02 in 4.5 minutes (not the 2 hours first estimated) with 4-8 processes per
# scenario: precise in 30 of 32 comparisons, see docs/redesign/STATUS.md. The same again with more
# processes, to settle the two imprecise cells, with the machine at rest.
a1 6b06dd2 6b06dd2 20 -suite dev -keys u64,str -sizes 4096,16384 -ops valuesFor,valuesBetween,churn,build -vs baseline -minprocs 8 -maxprocs 24 -skipmem

# The two real datasets with natural values (2026-10-03): street names with their localities and
# directories with their file names, ordered against the competitors of the multi profile, once with
# uint64 values (the value numbers) and once with strings (the real names, tags=strvals). Same
# commit and flags as the runs on the Windows PC (docs/redesign/step3-real-data.md). The estimates
# are guesses until the first job has run; the machine must be at rest.
r1 9847a43 - 60 -suite dev -keys street -values multi -sizes 4096,16384,212449 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3
r2 9847a43 - 60 -suite dev -keys dirs -values multi -sizes 4096,16384,86215 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3
r3 9847a43 - 60 tags=strvals -suite dev -keys street -values multi -sizes 4096,16384,212449 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3
r4 9847a43 - 60 tags=strvals -suite dev -keys dirs -values multi -sizes 4096,16384,86215 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3

# The page layouts side by side on the real keys (cmd/pagebench): the directory page of vpage and the
# length-header page of lpage, numbers and names as values, street and dirs. Diagnosis of the layouts
# in isolation; takes a few minutes on the PC. The machine must be at rest.
p1 b680abf - 15 gorun ./cmd/pagebench -keys street,dirs -validation 20 -repeats 61

# The tree with pages for string values (docs/redesign/step3-tree-pages.md, written 2026-10-04): the
# candidates ordered-lpage (one value per entry in the pages, copy-out strings), ordered-lpage-zc
# (immutable pages, strings that are views of the page), ordered-lpage-mv (entries with several values
# in the pages) against today's ordered and the competitors. The same flags as the PC runs lp3, lp4
# and lp5; the machine must be at rest. l1 and l2: one value per key; l3 and l4: the natural mix.
l1 c4dc4b6 - 25 tags=strvals -suite dev -keys street -values unique -sizes 4096,16384,212449 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3 -vs ordered-lpage,ordered-lpage-zc,btree-map
l2 c4dc4b6 - 20 tags=strvals -suite dev -keys dirs -values unique -sizes 4096,16384,86215 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3 -vs ordered-lpage,ordered-lpage-zc,btree-map
l3 c4dc4b6 - 45 tags=strvals -suite dev -keys street -values multi -sizes 4096,16384,212449 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3 -vs ordered-lpage,ordered-lpage-mv,ordered-lpage-mvzc,btree-sets
l4 c4dc4b6 - 40 tags=strvals -suite dev -keys dirs -values multi -sizes 4096,16384,86215 -minprocs 8 -maxprocs 24 -memn 262144 -memrounds 3 -vs ordered-lpage,ordered-lpage-mv,ordered-lpage-mvzc,btree-sets

# Step 4.2 gate on the M1 (2026-10-05, the night the user left the Mac free): the multi-key pages with the merge
# trigger of 3e1e952 against step 3.5 (fe120f5), real mix against btree-sets and one value per entry against btree-map.
# The PC runs the same commit (m43) with the sizes of the dev suite; here 65,536 keys too, where random uint64 keys
# are the worst case of the memory (docs/redesign/step4-probe.md).
m43 3e1e952 fe120f5 150 -suite dev -keys u64,street,dirs -values natural,single-value -sizes 4096,16384,65536 -memn 262144 -memrounds 3 -vs baseline,btree-sets,btree-map -minprocs 4 -maxprocs 8

# Gate 5 of step 5 on the M1 Pro (2026-10-07, rewritten the same evening): the deferred jobs, with the commit after the review
# (eb4a574: the tree on the one page, reads fixed, hysteresis between burst and merge; docs/redesign/review-2026-10.md). The cases
# of m44 / m46 / m47 on the PC. Three jobs, one build each; the user runs them in one night, one after the other:
#   bench/remote/arm-run.sh m48 && bench/remote/arm-run.sh m48s && bench/remote/arm-run.sh m48p && bench/remote/arm-run.sh pg1
# (m43 took 1h40 for the cases of m48, not the 150 minutes estimated; the estimates below are of that size.)
m48  eb4a574 fe120f5 100 -suite dev -keys u64,street,dirs -values natural,single-value -sizes 4096,16384,65536 -memn 262144 -memrounds 3 -vs baseline,btree-sets,btree-map -minprocs 4 -maxprocs 8
m48s eb4a574 fe120f5 65  tags=strvals -suite dev -keys street,dirs -values natural,single-value -sizes 4096,16384,65536 -memn 262144 -memrounds 3 -vs baseline,btree-sets,btree-map -minprocs 4 -maxprocs 8
m48p eb4a574 fe120f5 100 tags=ptrvals -suite dev -keys u64,street,dirs -values natural,single-value -sizes 4096,16384,65536 -memn 262144 -memrounds 3 -vs baseline,btree-sets,btree-map -minprocs 4 -maxprocs 8

# Step 5.5b (docs/redesign/step5-one-page.md): the page-level benchmarks of the one page (internal/page) and its placement
# benchmark (values at the end of the object or behind the byte area; cold: 64 MiB of pages, 128-byte cache lines here).
# A few minutes; the machine must be at rest.
pg1 eb4a574 - 12 gotest ./internal/page -run ^$ -bench Placement|BenchmarkPage$|BenchmarkFixed$|BenchmarkFixedPointers|BenchmarkOneKey -benchtime 300ms -count 3
# Experiment exp-maxkeys (2026-10-09, docs/redesign/autotune-design.md, "Experiment exp-maxkeys"): the curve of the autotune,
# Ordered with at most 1, 2 and 4 keys a page (ordered-mk1/2/4) against today's form (ordered), main (baseline) and the
# B-trees. One job for the whole night; the PC runs the same arguments. Start it with
#   bench/remote/arm-run.sh --yes mx1
# (on power; --yes answers the warnings, so nothing waits for an answer). About 4.5 to 5 hours; the Mac is free by 12:00.
mx1 99b00af cc47992 300 -suite dev -keys u64,street,dirs,url -values natural,single-value -sizes 4096,16384,65536 -ops valuesFor,valuesBetween,churn,build -memn 262144 -memrounds 3 -vs baseline,btree-sets,btree-map,ordered-mk1,ordered-mk2,ordered-mk4 -minprocs 4 -maxprocs 8
